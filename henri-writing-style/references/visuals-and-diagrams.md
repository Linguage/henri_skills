# 图像、插图与技术示意图

本模块适用于文章、研究综述、技术报告、博客和演示材料中的配图规划、原图选用、示意图绘制、图片改绘与图文排版。图像服务于正文中的具体信息，不承担装饰、宣传或作者自我说明。

## V1｜图片首先是图片，不是幻灯片

1. 图片主体直接呈现对象、场景、结构、数据或过程。默认不在图片内部添加大标题、副标题、章节名称、宣传语、结论句或说明段落。
2. 不把整张图设计成一页演示文稿。避免顶部刊头、标题横幅、底部总结栏、卡片式大段文字和无意义留白。
3. 图名、编号、来源、必要解释放在正文图注或相邻段落中，不嵌入图片主体。
4. 图片内部只保留理解图形不可缺少的标签、坐标、图例、变量名、单位和简短注释。标签应贴近对应对象，避免大段文字。
5. 不在图像内部放置免责声明、作者说明、绘图过程说明、版权提醒或“本图仅供示意”等防御性文字。必要的图示性质、假设和数据口径写入正文或图注。
6. 不为每张图强行添加标题和副标题。没有必要的文字就不加。

## V2｜图像与正文分工

1. 正文负责提出问题、解释机制、比较结果和说明意义；图片负责呈现空间关系、结构、流程、形态、趋势或视觉证据。
2. 图片不能代替正文解释。正文在图片出现前自然引出它，在图片之后说明读者应观察的具体关系。
3. 不在正文逐项复述图片中已经清楚标出的所有标签；应解释结构、差异、变化或与论点有关的细节。
4. 每张图只承担一个清楚的主要任务。多个任务之间没有直接关系时拆图；同一结构的多个状态或对比可以放在一张图中。
5. 图片没有增加理解价值时，不添加。避免为了达到数量而重复正文、重复表格或重复另一张图。

## V3｜技术概念图的绘制

1. 优先呈现技术对象本身：真实场景、几何结构、网络连接、输入输出、时间变化、物体运动或实验结果。
2. 流程图使用清楚的方向和层级；箭头必须表达真实的数据流、控制流、时间顺序或因果关系。
3. 对比图使用相同视角、尺度和视觉编码。只有比较对象确实不同的维度才改变图形。
4. 示意图不伪装成真实实验结果。没有数据时不绘制坐标曲线、精确数值或看似测量得到的统计图；可用明确的结构示意表达关系。
5. 不将不同论文的模块拼成某家公司的内部架构。综合图应标明它是跨研究的概念整理，并在正文解释来源关系。
6. 不把视觉风格当作信息。渐变、阴影、装饰线、拟物卡片和复杂背景只有在帮助辨认对象时才使用。
7. 默认使用克制的出版物插图风格：白底或低干扰背景、清晰轮廓、有限配色、统一线宽、足够对比度和可读字号。颜色应编码对象类别或状态，不作纯装饰。

## V4｜原图、改绘与来源

1. 论文原图能够清楚表达问题、分辨率合适且许可允许时，可以直接使用。
2. 需要翻译、合并多篇研究、简化结构或适配版面时，可以改绘；改绘必须忠实保留原图的技术关系，不得删掉会改变含义的模块、条件、箭头或实验组。
3. 直接使用原图时保留作者、论文、图号和必要版权信息；遵守出版许可。论文可下载不等于图片可自由转载。
4. 改绘图注使用“据……改绘”或“根据……整理”，列出实际来源。综合多个来源时说明各自支持的部分。
5. 自行绘制的概念示意图只标注其实际依据，不虚构论文原图、实验数据或机构归属。
6. 图片中的英文标签需要翻译时，保持术语与正文一致；必要时保留缩写和原文名称。

## V5｜图注与正文说明

1. 图注通常只包含图号、对象名称和必要来源。例如：“图3 多摄像头特征向鸟瞰空间的映射（据文献[6]改绘）”。
2. 不在图注中重复解释整张图，不写“本图旨在说明”“帮助读者理解”等作者自我说明。
3. 图中符号、颜色和缩写若不能从图形直接理解，可在图注用一句话说明；较复杂的机制放回正文。
4. 图片的实验条件、采样设置、单位、统计口径和必要限制写在正文或图注中，不塞进图像标题栏。
5. 正文应在图片前后建立联系：前文提出图中展示的问题，后文指出具体需要观察的结构或结果。

## V6｜版面与可读性

1. 图片按内容比例缩放，不拉伸、不压扁；保留必要的裁切边界。
2. 复杂架构图优先使用横向版面；纵向流程图按阅读方向组织。避免为了填满页面而放大空白。
3. 图片中的文字在实际阅读尺寸下必须清晰。无法读清时，裁剪无关区域、拆分图组或改用简化重绘。
4. 同一篇文章保持图形语言一致，但不要求所有图片长得一样；真实照片、论文原图、流程图和数据图可以并存。
5. 图片尽量与图注保持在同一页；避免图片单独占页、图注跑到下一页或正文引用与图片相隔过远。
6. Word和PDF均需检查实际渲染，不能只检查文档中是否存在图片对象。

## V7｜图像生成与编辑提示模板

### A. 技术概念图

> 绘制一张用于技术综述正文的概念示意图。直接呈现[具体对象／结构／过程]，重点表现[需要读者观察的关系]。采用出版物插图风格，背景简洁，结构清楚，线条和配色统一。图内只保留必要的对象标签、变量、图例和单位。不要添加大标题、副标题、章节名称、宣传语、总结框、免责声明或作者说明。不要虚构数据、实验结果或未提供的系统模块。

### B. 技术架构图

> 根据提供的论文或技术材料绘制架构图。严格保留原始模块、输入输出、连接方向、条件分支和训练／推理边界。模块名称使用与正文一致的术语。用箭头准确表达数据流或控制流。不要自行补充材料中没有的模块，不要将多个系统拼成一个未经证实的架构。图内不添加标题栏、副标题、总结文字或免责声明。

### C. 方法对比图

> 对[方法A、方法B、方法C]进行同尺度并列呈现。每个子图使用一致的视角、尺寸和视觉编码，只展示各方法真实不同的部分。图内保留必要标签，不添加解释性段落、宣传性结论或免责声明。比较依据和实验条件由正文与图注说明。

### D. 论文原图改绘

> 根据提供的论文原图进行中文出版物风格改绘。保留原图表达的技术关系、对象数量、箭头方向、空间关系和实验分组；只调整排版、文字语言和视觉清晰度。不得改变实验结果、删减关键条件或增加原图没有的结论。不要添加大标题、副标题、免责声明或作者说明。图注中注明原论文来源和“改绘”。

## V8｜交付前检查

- [ ] 图片主体直接呈现对象、结构、场景或数据，没有幻灯片式大标题和副标题。
- [ ] 图片内部没有免责声明、作者自述、宣传语或冗余解释段落。
- [ ] 图片与正文分工明确，正文在前后均有必要说明。
- [ ] 每个箭头、标签、颜色和模块都表达准确关系。
- [ ] 没有虚构数据、实验结果或企业内部架构。
- [ ] 原图、改绘图和原创示意图的来源关系准确。
- [ ] 图中文字在最终Word和PDF尺寸下可读，图注与图片分页正常。
