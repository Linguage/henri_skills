# 第一阶段：收件根目录分类与归位

把来源根目录（`INBOX_ROOT`，通常是 `Downloads/`）中的散落文件按**内容类型与用途**分类。已完成识别和命名的文档型内容移动到本地暂存根目录（`STAGING_ROOT`，通常是 `Documents/`）；未完成项继续留在收件区。不能只按扩展名机械分类，因为 PDF 可能是图书、论文、报告、讲义、标准或扫描件。

## 执行前确定两个根目录

- `INBOX_ROOT`：接收、查重、识别、待确认和短期处理区。
- `STAGING_ROOT`：已经完成整理的本地内容库；先检查并复用其中已有目录。
- 若用户指定其他位置，以用户指定为准，不硬编码 `Downloads` 或 `Documents`。
- 把用户说的 `tmp`、`书籍` 等称呼解析成绝对路径并复述确认。不得把 `Downloads/tmp` 解释为 `/tmp` 或 `/private/tmp`。
- 用户可以为图书、论文、其它文档和重复文件分别指定不同目标根目录；逐类型记录目标，不强制合并成单一 `STAGING_ROOT`。
- 从收件区归位到本地暂存库属于本阶段的正常移动；从本地暂存库备份到云端仍默认复制。

## 查重范围与目录创建

- 把查重来源当作白名单。用户说“只检查 OneDrive”时，禁止检查 Zotero、Documents、其它本地书库或缓存。
- 云端占位文件只用文件名、书名、逻辑大小、清单和已有日志比对，不为查重触发下载。
- 先审计目标根目录的现有分类。语义大致可容纳时复用已有宽目录，不为更精确而新增专题层级。
- 确实没有合适目录时，列出拟新增目录的绝对路径、收录范围和文件数量，等待用户确认后再创建。
- 同题但大小或版本不同的文件默认进入待确认状态；只有用户明确把“同书不同版本”也视为重复时，才归入重复目录。

## 文档型内容的语义去向

| 类型 | 默认去向 | 判断要点 |
|---|---|---|
| 图书 | `STAGING_ROOT/书籍/{主题}/` | ISBN、出版社、完整章节结构、专著或教材特征 |
| 期刊/会议论文、预印本、长综述 | `STAGING_ROOT/论文/{主题}/` | 作者—摘要—关键词—参考文献结构，期刊/会议/arXiv 信息 |
| 学位论文 | `STAGING_ROOT/学位论文/{主题或学位层级}/` | 学位授予单位、导师、答辩或学位声明 |
| 报告、白皮书 | `STAGING_ROOT/文档/报告与白皮书/` 或已有专题目录 | 发布机构、项目结题、行业/公司报告结构 |
| 课程讲义、演示文稿 | `STAGING_ROOT/文档/课程与演示/` | 课程、授课、幻灯片或讲义结构 |
| 技术资料、手册 | `STAGING_ROOT/文档/技术资料/` | 软件、设备、工程方法、操作或接口说明 |
| 行业标准 | `STAGING_ROOT/论文/行业标准/` | 标准编号、发布机构、实施日期与规范条款 |
| 文章、访谈、网页导出 | `STAGING_ROOT/文档/文章与访谈/` | 非正式出版的文章、访谈、网页存档 |
| 文献管理与整理记录 | 对应 `STAGING_ROOT/文档/文献管理/`、`整理记录/` | 清单、索引、导出、整理日志 |
| 无法关联的通用文档 | `STAGING_ROOT/文档/杂项收容/` | 已确认不是书籍、论文或敏感档案，但暂无稳定主题 |

目标库已有语义相近的目录时优先复用，不为单个文件机械新建新类别。书籍、论文和一般文档的进一步规则分别见后续阶段。

## 非文档型内容

- 图片、视频、音频、安装包和数据集：先寻找用户已有的长期目录；存在明确主题关系时可以归入对应项目或资料目录。
- 无法确定长期去向时，移入 `INBOX_ROOT/_待处理/`，不要为了清空 Downloads 擅自在 Documents 中创建宽泛目录。
- 未完成下载与短期中间状态进入 `INBOX_ROOT/临时文件/`。
- 系统文件、已确认重复和待清理产物进入 `INBOX_ROOT/待删除/` 等候复核，不直接删除。
- 压缩包不为查重而强制解压；可先集中到同一待核验目录。

图片如需按来源细分，先使用 `classify_images.py` 的报告模式，确认后再执行移动：

```bash
python <skill-dir>/scripts/classify_images.py --scan-root <PATH>
```

## 敏感文档识别

在整理文档前，必须识别可能包含个人信息的文件，并提示用户单独存档。

**敏感文档特征：**

- 姓名标识、学校或机构信息；
- 登记表、申请表、证明、证书、成绩单、简历；
- 法院、合同、银行、税务、工资与发票资料；
- 身份证、护照、驾驶证等证件。

**处理方式：**

1. 单独列出并标注“敏感文档”；
2. 询问是否存入 `STAGING_ROOT/个人档案/`、`STAGING_ROOT/文档/受限资料/` 或用户指定位置；
3. 用户确认后再移动，不把敏感内容放入普通杂项目录。

## 工作流程

1. 明确 `INBOX_ROOT`、`STAGING_ROOT` 及保留策略。
2. 按用户授权的查重白名单盘点重复候选，不扩展到未授权的库。
3. 审计每个目标根目录的现有目录，建立只复用已有宽分类的目标映射。
4. 综合文件名、元信息、首页/目录/摘要与必要的 OCR 判断实质类型，并检测敏感文档。
5. 在来源目录生成重命名计划；列出映射并确认后先执行重命名，保存日志。
6. 对无法使用现有目录承载的文件，列出拟新增目录并单独等待确认。
7. 基于重命名后的文件名生成移动计划，列出全部操作并等待确认。
8. 使用安全移动清单预检；不同目标根目录使用独立计划，不把目标根设为 `/`。
9. 执行后核对源、目标和数量，只清理由本批次产生的空目录与临时产物。
10. 把正式整理日志放入约定的隐藏 `.log/` 或用户指定位置；更新实际发生变化的管理文档。
